# 6.1.5 response observation follow-up

The integrated 6.1.5 turn `f4af1e46cb59` failed at 2026-10-07T10:31:40.419Z. Its `session_alert` probe consumed 20,002 ms. Before failure, revisions 3 and 5 had completed capture, ACK reception and tool emission. The failed tab was released at 10:31:40.426Z. This is an observation failure after acceptance, not a missing Send or tool ACK.

The response loop previously recovered observation timeouts only inside `reconcileAssistantTurnBinding`. The session alert, delivery alert and response projection ran outside that recovery catch. The assistant-binding loop had the same gap for its preliminary session/rate-limit checks.

This patch routes response observation timeouts through the existing same-page reconnect, with the existing maximum of two consecutive reconnects. It preserves accepted user/assistant identities, the submission baseline and the tool-boundary tracker. Cached DOM and completion-fence evidence are invalidated before another read. Cancellation, deadlines, explicit account errors and boundary errors remain terminal; no message is resent and no missing ACK is inferred. Persistent failures use `browser_observation_recovery_exhausted`; individual timeouts carry the probe name and `browser_observation_timeout`.

Account-error polling now reads alert/dialog roots once, pruning user messages, answer prose and quoted code. Text retained per subtree is capped at 1,024 characters; only a matching short UI element needs visibility/layout checks. Nested roots share the traversal. Hidden error copies and quoted account-error strings cannot establish an expired session. A failed projection remains an observation failure rather than silently becoming an absent alert.

Validation executes the actual response-loop catch with delayed observation, repeated failure, cancellation, deadline and explicit-error fixtures. Assistant binding and cancellation use the real worker methods. Browser fixtures exercise 320,000 and 1,000,000 characters, nested prose, localized and split account-error copy, hidden errors, and preservation of all input text. The same session projection is extracted from both compiled runtime bundles. Existing focused model/effort, multipart, response completion, IPC ACK, rendering and terminal-tab-release fixtures cover the affected contracts. All browser fixtures are offline and send no worker or Pro messages.

The renderer queue cause is not established by this patch: live read-only DOM metadata took 1.1–1.7 ms in pages of 533,533–815,390 characters while the failing historical probe waited 20 seconds. The patch repairs the fatal recovery gap and reduces error-scan work; it does not claim to eliminate persistent renderer stalls or all memory growth. Full live recovery requires a naturally occurring timeout after installation.

Installation uses a fresh full manifest-verified 6.1.5 runtime, the unchanged launcher archive, a full backup of the prior integrated runtime, and an independently armed restart guardian. Completion requires its reservation `state.json` to contain `phase: complete` and `healthyAt`. Active turns are recorded before replacement. Claude, its guardian/logger and unrelated training processes are outside the transaction.
