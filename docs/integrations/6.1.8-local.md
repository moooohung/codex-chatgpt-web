# Upstream 6.1.8 integration (2026-10-12)

The integration follows the user's rule: upstream code and behavior take priority
when an upstream change conflicts with a local patch. The release baseline is
`miuuyy/codex-chatgpt-web` tag `v6.1.8`. Compatible source-controlled local features
remain; generated-file overlays are not a source of authority.

## Conflict decisions

- Keep upstream's six-part compaction planning and GPT-6 Plus composer ceiling.
  Retire local compaction assumptions that required two parts or oversized input.
- Keep upstream's exact-turn MCP acceptance independent of renderer responsiveness.
  Acceptance does not release tools. The response loop still captures the boundary,
  records observation and acknowledges it before the broker can emit tools. Its
  existing cancellation and boundary error tests remain enabled.
- Keep upstream's owned generation/SSE progress semantics and security-check errors.
  Adapt the local daemon watchdog to actual generation progress. Heartbeats do not
  extend the generation deadline.
- Keep upstream's repeated workspace-root delta contract and deduplication. Retain
  local exact-rollout proof, native user-revision/date handling, retry identity and
  compaction continuity without using cached thread registration as authorization.
- Keep upstream large-attachment processing, markdown parsing, multipart history,
  completion checks and model-selection verification. Bound the additional
  diagnostic structure capture so error reporting cannot hold a failed turn open.

## Normal Chrome login on Windows and Linux

The existing macOS normal-Chrome login flow is exposed on Windows and Linux too.
Google authentication occurs in a dedicated, normal Chrome profile before any
Playwright connection. After the user selects Continue, the owned browser closes
normally and only allowlisted ChatGPT/OpenAI state is captured offline. Windows
checks the process identity, executable and exact private profile argument before
requesting a normal window close. It fails without importing a session when that
ownership or close cannot be established. Embedded-browser identity is not altered.

The button and lifecycle are covered by offline launcher fixtures on all supported
platforms; Windows ownership failures are tested with inert PowerShell cmdlet mocks.
Those fixtures do not prove a live Google authentication or macOS/Linux runtime login.

## Retired installed overlays

Comparing the installed 6.1.7 bundles with the source build found nine CLI scope
changes and three repeated helper scope changes outside source control. The 6.1.8
package is rebuilt from source and does not reapply them:

- Prompt text claiming blanket tool authorization and weakening safety handling.
- Suppressed markdown consistency/range errors.
- Unverified effort selections, origin-only URL assertions and hidden or substring
  connector matching.
- Cached-environment fallback before native rollout proof.
- An external generated-code token telemetry hook loaded from a separate patcher.

The legacy binary patcher is not invoked. Its old overlays must not be reapplied to
this release; future compatible changes should be implemented and tested in source.

## Build and installation contract

Bun **1.4.2** is deliberately pinned to the official 6.1.8 release toolchain,
matching its runtime bundler, type declarations and version checks. This is a
release-reproducibility pin, rather than a claim that 1.4.2 is the newest Bun.
Electron 44.7.0 and Playwright 1.64.0 remain unchanged.

Installation uses a hashed full-runtime plan, complete bundle validation, isolated
failure/rollback fixtures and an independently armed relaunch guardian before
requesting launcher shutdown. Installation success requires installed-file hash
readback and restart-reservation `phase: complete` with `healthyAt`. Paid/Pro test
prompts, real authentication and unrelated application restarts are outside these
offline checks.
