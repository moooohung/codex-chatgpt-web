# Upstream 6.1.9 integration (2026-10-14)

The official stable release is tag `v6.1.9`, resolved to
`c815a907a91af75f86a02218bd4ff3dc819a183f`. Upstream behavior takes
priority over overlapping local patches. The parent is the reviewed 6.1.8
integration at `4c10d2f3cf9bdc31e173c66b32312e943bc287e4`.

## Conflict decisions

- Adopt upstream's bounded Electron page-script helper, primary renderer recovery,
  authentication revision invalidation and system proxy resolution. Retain the
  destroyed-view guards, named Chrome login and actual leased-account proof.
- Adopt upstream's same-page submission transport cancellation and renewed
  acceptance observation. Cancellation retires the old keyboard transport;
  it is not evidence that the physical request was accepted and never authorizes
  another Send. Existing audited submission recovery and tool capture -> observe
  -> ACK contracts remain in force.
- Replace the old diagnostic pruning implementation with upstream's lifecycle
  history: live captures are protected and recent failures are retained. Keep the
  local terminal diagnostic budget at 250ms and release completed leases before
  diagnostic capture, so a stalled renderer cannot retain a finished large tab.
- Adopt upstream's bounded broker retirement diagnostics; retain the additional
  content-free retirement origin to distinguish timeout, expiry and shutdown.
- Keep both native compaction-continuation proof and upstream composer-prediction
  classification. Keep separate tests for staged-compaction policy and prediction
  configuration rather than replacing either during the merge.
- Preserve upstream default-on composer predictions, their explicit opt-out,
  GPT-6 Sol Medium model, full-context fit requirement, and absence of tools.
  No live suggestion or Pro request is part of upgrade verification.
- The optional prediction preflight still uses upstream's configured-account
  budget before opening any tab. In a mixed Plus/Pro pool it may conservatively
  skip a suggestion that a later Pro lease could fit. Actual task preparation
  continues to enforce the leased account's budget. Retain this upstream-first
  policy rather than widening admission on unproven account availability.
- Keep the compatible per-leased-account Bigger Context budgets, unsent failover
  preparation, Plus effort fallback, login/cooldown distinction, resource budget
  and tab-release policies. The native catalog still has one context window per
  model slug; response metadata does not retune a running client's threshold.
- Reconstruct the installed-only account capability overlay in reviewed source:
  fresh partition plan proof selects available Pro accounts for max requests;
  eligible paid non-Pro accounts remain the fallback. Picker Extra High evidence
  must match the leased account hash and plan. Persisted diagnostic entries are
  not routing proof: they reset to zero and are excluded until re-proved. Only
  an explicitly unsent, non-retained turn may fail over after a capability error.
  This replaces the untraceable generated runtime overlay rather than copying it.

## Toolchains and skill provenance

Bun 1.4.2 and the runtime dependency graph remain pinned to the official release
for reproducibility. Electron is pinned to 44.7.2, verified against the npm stable
registry on 2026-10-14; the entire Windows engine is packaged and verified together.
This preserves the user's current stable engine rule without reverting upstream
application behavior. Dependency update workflows remain enabled.

`skills/pro-researcher` is copied verbatim from upstream commit
`889f291d06339400a8b9c2941473f65cd47d4830`, published after the release tag.
The same files are installed in the user's Codex skills directory. Installation
does not run research or consume Pro quota. The original skill requires an
available Pro-capable sub-agent tool; availability is a runtime prerequisite,
not something skill installation can supply.

## Verification and installation

Required gates are version alignment, dependency audits, root and launcher
typechecks, focused and full offline suites, inert Chromium/Electron regression
fixtures, runtime/renderer builds and relocatable bundle smoke. Initial upstream
fixtures were adapted to the retained alert projection and extra broker origin;
production acceptance and ACK checks were not weakened.
The two captured Think UI shapes now have a 60s inert Electron test budget for
24 physical clicks, and upload fixtures await delayed CDP activation settlement
before asserting its error. Neither adjustment widens production timeouts.

Package receipts record executed checks, skips and exact reviewed identities.
Generated installed overlays have no authority over reviewed source. Production
replacement requires fresh original hashes, an independently armed guardian,
an idle/drained maintenance transaction, complete runtime/engine hash readback,
and restart reservation `phase: complete` with `healthyAt`. Account profiles and
unrelated work processes are outside the replacement plan. Live provider turns
and actual authentication are not proven by offline checks or process startup.
