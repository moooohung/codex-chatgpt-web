# 6.1.13 memory follow-up (2026-10-21)

Extends local commit 704ad8b without reducing request overlap or the eight automatic-tab slots.
Upstream model selection, compaction, prompt transport, tool safety, ACK and completion semantics
remain the authority. No provider or Pro test messages were sent.

## Changes

- CLI commands import their own implementation on demand. The runtime bundler now emits hashed
  chunks so external browser, prompt/tokenizer, DEV and setup packages are not eagerly evaluated
  in each long-lived MCP process. A source-only dynamic import without runtime splitting did
  **not** produce a convincing memory reduction and was not treated as evidence.
- The existing token-rejection classifier moves unchanged to a small module. `prompt.ts` keeps
  its previous exports; MCP no longer imports the complete prompt compiler for this classifier.
- Tab snapshots expose `memoryState` (running, retained, suspended, failed, other) using existing
  ownership/lifecycle flags. Snapshot polling adds no DOM reads or memory probes.
- The first patch remains included: synchronous allocation reservations, hidden terminal-failure
  cleanup after 60 seconds, revision-cached submission observations and automatic-view spellcheck
  disabled. Visible selected failures preserve the upstream inspection period.

## Evidence and limits

Production baseline is the tower's supplied sample: 19 processes, about 9.0 GB private memory;
renderers mostly 600-850 MB, largest 2244 and 1517 MB; three MCP processes about 400 MB each;
serve about 700 MB; GPU about 490 MB. This work did not resample a new production baseline.

Separate, isolated paired MCP startup probes (same Bun 1.4.2, no broker/provider activity) measured
536.5-564.4 MiB private / 145.5-147.0 MiB working set before versus 313.5-325.0 / 54.5-55.9 MiB
after. Initialize plus tools/list took 353.6-608.8 ms versus 108.8-151.9 ms. All six native tool
schemas had the same SHA-256. Tools/list median was 0.424-0.483 ms versus 0.363-0.450 ms;
P95 was noisy (0.764-0.818 versus 0.592-1.256 ms), so no per-call speedup is claimed.

An isolated idle serve probe did not demonstrate private-memory savings: 494.0-507.1 MiB before
versus 523.0-544.7 MiB after, although working set was 151.9-152.3 versus 145.1-146.8 MiB.
Health latency is not whole-turn latency. Production after measurements must include workload
state; a restart/idle sample is not a matched five-worker throughput benchmark.

The first patch's browser fixtures measured 100 unchanged projection observations: 71.8 to 0.1 ms
at 320k characters and 138.8 to 0.3 ms at 1M characters. These are DOM observations, not provider
generation times or total application RAM savings. They preserve multipart/assistant identities.

Do not remove transcript DOM nodes: React state and bridge turn/ACK identity still depend on the
real conversation. Idle parking already unloads completed saved-chat documents; its suspension
log records the memory **before** unloading, so a value above 512 MiB is not proof that recycling
failed. No new fresh-chat requests, forced GC loop, serial queue, network/login block, account or
model change was introduced as a memory optimization.
