# 6.1.12 Pro approval observation stability (2026-10-20)

This candidate addresses the approval-wait timeout demonstrated in five saved-chat Pro traces. It does not establish a fix for every Pro failure. Installation and provider prompts are outside this assignment.

These responsive DOM timings do not support attributing these five failures to DOM size, memory growth, or renderer starvation. The active browser views already disable background throttling. ## Source changes

- The worker runs manual approval policy outside an aggregate response-probe deadline. Each browser read, wait, click and status callback still has a bounded observation budget and cancellation fence. Tool boundary observation remains live throughout the approval wait.
- A failed approval visibility read now propagates rather than being treated as dismissal. Expiry still selects the unique Deny action; explicit auto-approval still selects only the unique one-time Allow action after Stop disappears.
- Boundary failures log only a fixed exception-kind whitelist, never an exception message or stack.
- Launcher test concurrency is capped at two to avoid a large parallel process fan-out on the shared host. This does not change runtime behavior.
- The reviewed full-bundle installer is adapted for this candidate, with exact fixture roots, hash validation and two-thread file copying. It contains no process termination operation.
