# 6.1.13 memory lifecycle follow-up

Baseline: integrated source `40465fdb082d602eb49649426df4f6c24ec033aa`, upstream
`v6.1.13` / `6f43747eb5585ca623c0617e729826dfd680c5b7`.
Candidate: `bridge-6113-memory-20261021`. Electron remains pinned to upstream
44.9.0; no dependencies, account limits, request concurrency or routing settings change.

## Findings

The previous memory patches are present in the installed archive and helper:
history/input content visibility, reduced motion/sidebar rendering, selective
resource blocking, idle-tab parking, and renderer recycling. Read-only CDP
confirmed the rendering attributes on current automatic pages. Missing input
attributes on an attachment-only page do not establish a selector regression.

The initial live sample contained eight automatic tabs and one home tab, plus
the launcher UI. CDP iframe and worker targets are not additional browser tabs.
The installed Electron processes used approximately 6.7 GiB working set during
that active workload; individual large active renderers consumed roughly
0.7–1.1 GiB. Completed-page parking was already replacing large renderers.
These changing workloads are not a controlled before/after memory benchmark.

Two independently reproduced retention/allocation problems remain relevant:

* Automatic allocation awaited locale setup before registering its slot. A
  synthetic simultaneous burst created 32 views with an eight-tab limit.
* A terminal failed page remained loaded for 30 minutes, even when hidden.
  Four such error tabs were visible in a later read-only launcher snapshot.

## Changes

* Reserve the automatic slot synchronously before yielding. Preserve all eight
  concurrent slots; overflow uses the existing capacity response. Release the
  exact native view on partial setup failure or cancellation during locale setup.
* Retain hidden terminal failures for one minute, then use normal tab removal
  and `webContents.close()`. Preserve the 30-minute upstream diagnostic window
  while the user is actually viewing the failed page. Active ownership is not
  subject to this terminal cleanup.
* Check the DOM observer revision before copying the transcript or walking
  rendering roots. Store only numeric metrics, not nodes or copied text. Drain
  pending mutation records before considering a cache hit. Budget changes
  invalidate the metrics; tool boundaries still read current turn identities.
* Write rendering attributes only when changed. Disable spell checking for
  automatic machine-generated input, including recycled automatic views.

The boundary capture -> observe -> ACK order, stable identity assertions,
model/effort selection, submission errors, lossless multipart content and
completion rules remain unchanged.

## Verification

* New allocation/lifecycle tests reproduce the race on the baseline. Candidate
  admits eight of 32 concurrent initializations and leaves no live views after
  20 burst/release cycles. Cancellation and each partial setup failure release
  only their own slot.
* Launcher tests: 693 pass, 9 skip; root tests: 1,537 pass, 175 skip. Root and
  launcher TypeScript checks pass. The three DOM test doubles now provide the
  standard MutationObserver.takeRecords method; identity assertions are unchanged.
* Isolated real Chromium: nine large-page tests pass (320k, 1M and 1.2M chars),
  including model/effort, multipart ACK, boundary/ACK/completion, duplicate turn
  rejection, same-task mutation invalidation and zero-copy unchanged reads.
* Unchanged synthetic 1M page, 100 projection calls: baseline 138.8 ms,
  200,004,800 text characters read, 2,300 attribute writes; candidate 0.3 ms,
  zero text reads and zero attribute writes. See the adjacent evidence JSON.
  This measures DOM work, not total provider renderer memory or end-to-end speed.
* A separate hidden Electron 44.9.0 fixture confirmed renderer exit after normal
  closure. Spellcheck on/off did not demonstrate a memory reduction in that
  simple fixture; no savings claim is based on that toggle.
* Live cleanup selected only unselected terminal failures older than one minute,
  with matching failure-log and fresh tab identity evidence. The normal launcher
  close API released three renderers; all three PIDs exited. Those processes
  accounted for 1,832.4 MiB private memory before release. Total installed Electron
  working set changed from 6,957.4 to 4,873.4 MiB during that workload. Active work
  continued; the total is an observational sample, not a controlled RAM benchmark.
* The freshly built CLI and helper also passed all six 320k/1M model, effort,
  multipart, boundary/ACK and completion fixture cases.

Source-built runtime and NSIS package use a new immutable plan and independent
guardian. Run isolated installation, full rollback and three injected failure
rollback checks before live replacement. Do not stop active work for installation.
Live deployment requires a complete restart receipt, healthyAt, process health,
all replacement hashes and the complete active runtime cache to match the plan.
No provider prompts, Pro tests, user jobs or unrelated processes are part of
these verification fixtures.
