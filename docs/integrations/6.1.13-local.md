## Conflict decisions

- Use upstream's native compacted-environment recovery, filesystem-profile
  validation and calendar-delta checks. Preserve strict request-scoped native
  compaction admission and verified failed-turn retry boundaries. An admitted
  snapshot must still match its original request; it cannot authorize mutation.
- Use upstream's single plain `turn_token` continuation instruction and configured
  plugin name. Retire the overlapping local JSON binding envelope, and adapt the
  harness and DEV fixtures to the upstream token format. Retired-handle
  sanitization and Native2 recursive-dispatch exclusion remain.
- Keep upstream's five-minute compaction inactivity budget and suspend-aware
  progress clock, replacing the local fifteen-minute limit. Real progress renews
  the inactivity budget; suspension does not consume it. Preserve physical-owner
  settlement, cancellation and committed-checkpoint ownership.
- Use upstream's explicit size-rejection classification and identical-input
  rejection caching. Preserve the physical Send activation gate on every
  multipart Send, alert-baseline capture, observe-before-ACK and completion checks.
- Use upstream's manual approval expiry error. Expiry never clicks Deny. Preserve
  auto-approval settings across upgrades as upstream now requires; no production
  approval-setting restart or paid tool invocation is asserted by this merge.
- Keep local bounded DOM observation, account leases, actual leased-account
  capability preparation, effort ceilings, multipart metrics and rendering
  reductions. Avoid duplicate unbounded observation probes. Forward the actual
  worker plugin name through prompt and usage preparation.
- Use upstream CI packaging/signing configuration and its pinned Vite patch.
  The existing release workflow and dependency-update automation remain enabled.

The upstream environment test suite replaces overlapping local environment tests;
the dedicated local native admission/retry tests still exercise their stricter
request and mutation boundaries. Preserve the release's dependency lockfiles and
the reviewed Bun 1.4.2 / Electron 44.9.0 toolchain for reproducibility.

## Authorized installation and receipt

The user authorized installation. Stage backups while the launcher is live, then
refresh live hashes, process identity, health and protected jobs. The reviewed
maintenance script requires isolated route preflight before arming and again before
drain/quit; never hand-edit routing or an integration journal to force it through.
Wait for idle without active-turn cancellation. Require matching `armed.json` and
`guardian-ready.json` before quit and use only the normal maintenance transaction.

Installation is proven only by the new reservation's `state.json` with `complete`,
valid `healthyAt` and successful operation, plus installed and active-cache hash
readback and healthy turn admission. Earlier failed reservations are historical
evidence, not successful installation. Write exact current results and remaining
limits to the candidate's `upgrade-result.json`; build success alone is insufficient.
No Pro/paid prompt, unrelated process shutdown, STS2 work-file modification or
automatic job relaunch is part of this update.
