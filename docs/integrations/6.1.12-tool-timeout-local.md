# Native2 recursive connector dispatch timeout (2026-10-20)

This candidate prevents this bridge from forwarding its own connector tools as outer native tools. It addresses the recursive dispatch observed in two saved Pro job traces. It does not prove that every codex_apps latency, account-switch or connector attachment failure is resolved. Stop before installation; no provider prompt is part of this work.

## Observed failure and inference

Job `pro_yaho_chess_blender_1`, thread `01a15975-fb63-7840-9dd8-e72ea917018c`, contains two recursive dispatches. The active `codex_tool_call` queued `mcp__codex_apps__codex_native2___codex_exec` back into the connector whose original call was still waiting. The source allowed this connector wire into the native inventory and dispatch path. A dedicated `codex_exec` request normally selects the genuine local `exec_command`/`shell_command` or native JavaScript gateway instead.

The two matching orderings strongly support serialized re-entry: the nested request waits until the original MCP invocation times out. The 90-second interval is before the nested request's tunnel dispatch/bridge receipt, not in the shell command or boundary ACK. Available evidence does not distinguish an internal Codex MCP-client queue from the apps connector/control-plane queue. No current per-request app-server/codex_apps retry, auth-refresh or tools/list log was found; the local process registry and other Codex logs were stale. Do not label the exact private queue as proven.
